# fix(endec): write an empty pattern as a regex literal that parses

- **Date:** 2026-10-14 14:34
- **Commit:** 0cad74d6
- **Area:** `macroforge_ts` Encode and Decode

## Problem

`@endec({ validate: ['pattern("")'] })` generated `//`, a line comment, where the check of the
field's text stood.

## Cause

`regex_body` wrote a pattern's text between two slashes as it was, and an empty one leaves `//`.

## Introduced

`63a9a5b3` (2026-10-13, "fix(endec): refuse a pattern that is no regular expression") added
`regex_body`.

## Fix

An empty pattern is written `/(?:)/`, which matches what it does.

## Verified

Ran `cargo test -p macroforge_ts --features test-macros --lib` (776 passed), whose property parses
each pattern the check takes, written as a literal, with oxc, and the `edge-scanned` testground
suite, which decodes a field checked by `pattern("")` with empty text, text, `//` and a line break.
