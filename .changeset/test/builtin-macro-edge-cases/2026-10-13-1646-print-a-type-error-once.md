# fix(cli): print a type error of generated code once

- **Date:** 2026-10-13 16:46
- **Commit:** 1629c245
- **Area:** `macroforge tsc`

## Problem

A derive whose generated code fails to type-check in three places for one reason, as three calls of
a function that does not exist, printed the same line three times:

```
src/holder.ts(11,5): error TS2304: in code generated by Decode: Cannot find name 'plainDecodeWithContext'.
src/holder.ts(11,5): error TS2304: in code generated by Decode: Cannot find name 'plainDecodeWithContext'.
src/holder.ts(11,5): error TS2304: in code generated by Decode: Cannot find name 'plainDecodeWithContext'.
```

## Cause

The wrapper moves each diagnostic from the expansion onto the source. Every position in generated
code maps to the decorator that generated it, so diagnostics that differed only in where they stood
in the expansion came out alike, and each was printed.

## Introduced

`2aabc445` (2026-10-08, "feat(core)!: add $Newtype brands and check primitive values on decode")
moved the wrapper's diagnostics onto the source, and printed each as it came.

## Fix

The wrapper prints each distinct line once. The exit status is unchanged: one error is one error.
