# fix(tooling): update the Deno lock when bumping the version

- **Date:** 2026-10-21 12:58
- **Commit:** fac57cc3
- **Area:** `mf bump`

## Problem

After `pixi run bump`, `deno.lock` still recorded every workspace package at the old version, so the
bump commit left the lock behind the manifests until the next install rewrote it.

## Cause

`mf bump` updated the manifests, the Cargo locks and the API data, and never the Deno lock.

## Introduced

`cca06306` (2026-09-21, "feat!: publish the engine as @macroforge/core and root both workspaces")
rooted both Deno workspaces in one `deno.lock` that records each workspace package by version, and
`mf bump` did not follow.

## Fix

`mf bump` runs `deno install` from the root after the Cargo locks, as `mf verify` installs.

## Verified

`cargo test -p mf bump` passed, 3 of 3, and `target/debug/mf bump --version 0.6.0` brought
`deno.lock` to 0.6.0 with the manifests, changing the version alone.
